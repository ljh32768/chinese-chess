# 局域网象棋 MVP 产品设计文档

- 版本：v0.1
- 状态：MVP 草案
- 类型：局域网两人中国象棋
- 目标：验证核心玩法、联机流程和界面操作是否合理

---

## 1. 产品定位

一个局域网内两人实时对战的中国象棋游戏。

核心目标：

> 两台设备连上后，能完整、正确地下一盘棋。

MVP 不追求账号、匹配、公网、排行榜等外围能力，优先把“连接、走子、裁判、同步、重开”跑通。

---

## 2. MVP 目标

- 同一局域网内，两台设备连接。
- 一方创建对局，一方加入对局。
- 支持完整中国象棋走子与胜负判定。
- 走子实时同步，非法走子被拒绝。
- 能认输、和棋、重开、离开。
- 断线有提示，程序不崩溃。
- 能完整下完一盘棋。

---

## 3. MVP 非目标

以下功能不进入 MVP：

- 账号系统、注册登录
- 公网联机、NAT 穿透、匹配服务器
- 排行榜、战绩
- AI 对手
- 观战、回放
- 多房间、大厅、房间列表
- 房间号、密码、准备状态
- 自动发现局域网主机
- 断线重连
- 悔棋
- 计时、读秒
- 长将、长捉、重复局面、自然限着等复杂裁判规则
- 皮肤、音效、动画
- 复杂聊天系统

---

## 4. 核心设计原则

1. **对局即连接**
   - 不设计房间列表、房间号、密码、大厅、准备状态。
   - 连接成功即视为对局成立。

2. **主机权威**
   - 创建对局的一方维护唯一棋盘状态。
   - 主机负责规则校验和胜负判定。

3. **加入者请求**
   - 加入者只发送“我想怎么走”。
   - 由主机判定是否合法。

4. **简单同步**
   - 每步广播完整棋盘状态。
   - 数据量小，稳定优先。

5. **规则先行**
   - 规则引擎与 UI 分离。
   - 先保证走子、将军、将死、困毙正确。

6. **文案可叫“房间”，底层不做房间系统**
   - UI 可以使用“创建对局 / 加入对局”。
   - 底层不需要 `roomId`，连接本身就是对局。

---

## 5. 用户角色

### 5.1 主机

- 创建对局
- 启动监听
- 显示本机 IP 和端口
- 默认执红
- 维护权威棋盘状态
- 校验加入者走子请求
- 广播对局状态

### 5.2 加入者

- 输入主机 `IP:端口`
- 发起连接
- 默认执黑
- 发送走子请求
- 接收主机广播并渲染棋盘

---

## 6. 核心流程

### 6.1 创建对局

1. 主机点击“创建对局”。
2. 显示本机地址，例如 `192.168.1.42:7777`。
3. 进入等待连接状态。
4. 对手加入后自动开局。

### 6.2 加入对局

1. 加入者点击“加入对局”。
2. 输入主机地址和端口。
3. 点击连接。
4. 连接成功后自动开局。

### 6.3 对局中

1. 红方先走。
2. 当前玩家点击己方棋子。
3. 界面显示合法落点。
4. 点击合法落点后发送走子请求。
5. 主机校验。
6. 合法则更新棋盘并广播。
7. 非法则拒绝并提示。
8. 切换回合。
9. 判定将军、将死、困毙。

### 6.4 对局结束

1. 出现将死、困毙、认输或和棋。
2. 弹出结果：红胜 / 黑胜 / 和棋。
3. 显示原因：将死、困毙、认输、同意和棋。
4. 可选择“再来一局”或“返回首页”。

## 8. 规则裁判要求

### 8.1 必须支持

- 车、马、炮、象、士、将、卒合法走法
- 不能吃己方棋子
- 不能送将
- 将帅不能照面
- 将军提示
- 被将军时必须应将
- 将死判负
- 困毙判负
- 认输判负
- 双方同意和棋

### 8.2 MVP 不做

- 长将
- 长捉
- 重复局面
- 自然限着
- 悔棋
- 计时
- 读秒

---

## 9. 联机同步设计

### 9.1 同步模式

采用 **主机权威模式**。

- 主机维护唯一真实棋盘状态。
- 加入者发送走子请求。
- 主机校验合法性。
- 合法则更新棋盘，并广播结果。
- 非法则拒绝，并返回原因。
- 每步带序号 `seq`，防止重复、乱序。

### 9.2 同步内容

MVP 可以每次广播完整棋盘状态。

示例：

```json
{
  "type": "move_applied",
  "seq": 12,
  "from": [9, 0],
  "to": [7, 0],
  "board": "...",
  "turn": "black",
  "check": false,
  "gameOver": false
}
```

### 9.3 常用消息

- `join`
- `start`
- `move`
- `move_applied`
- `move_rejected`
- `resign`
- `draw_request`
- `draw_response`
- `restart_request`
- `restart_response`
- `game_over`
- `ping`
- `pong`
- `disconnect`

## 13. 技术方向建议

- 桌面 / 移动原生：主机监听 TCP 或 WebSocket，加入者输入 IP 连接。
- Web 端：浏览器不能直接当 TCP 主机，需要本地服务端或 WebSocket 服务端。
- 规则引擎与 UI 分离，方便单元测试。
- 通信格式使用 JSON。
- 主机权威，客户端只做渲染和输入。
- 连接、开局、走子、重开建议都走消息协议，不要依赖 UI 状态互相猜测。

---

## 14. MVP 验收标准

满足以下条件即视为 MVP 完成：

- 两台设备在同一局域网。
- 主机能显示本机地址并等待连接。
- 加入者能通过 `IP:端口` 加入。
- 双方能轮流走子，棋盘同步。
- 非法走子会被拒绝。
- 将军、将死、困毙判定正确。
- 能认输、和棋、重开、离开。
- 一方断线，另一方有提示且不崩溃。
- 能完整下完一盘棋。

## 17. 一句话总结

MVP 只做：

> 局域网两台设备 + 主机/加入主机 + 完整中国象棋规则 + 主机权威同步 + 胜负与重开。

其他功能全部后置。
